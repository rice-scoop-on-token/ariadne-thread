# UX 흐름 명세 (ux-flow.md)

본 문서는 아이디에이션 시각화 서비스의 UX 흐름 확정본이다. 초안 검토에서 도출된 수정 사항을 반영했으며, 변경 내역은 8장에 정리한다.

단계 참조는 **숫자 대신 고정 ID(P0~P8)** 를 사용한다. 초안에서 단계 번호 참조가 어긋난 원인이 중간 단계 삽입에 따른 번호 이동이었으므로, 이후 단계가 추가되어도 ID는 변하지 않도록 고정한다.

---

## 1. 설계 원칙

각 원칙은 실험 근거에서 도출되며, 본 문서의 화면 노출 규칙과 개입 설계의 전제가 된다. 근거 문헌은 `docs/research-references.md`를 참조한다.

- **발산 구간은 텍스트, 수렴 구간은 시각화로 분리한다.** 브레인스토밍은 아이디어 개수에서, 브레인스케칭은 이전 아이디어와의 연결에서 각각 우위를 보였다. 두 기능을 동일 화면에서 제공하면 양쪽 모두 손실된다.
- **완성도 높은 시각 표현은 고착을 유발하므로 단계적으로 개방한다.** 예시 해법을 제시하면 결함을 명시해도 새 설계가 그 특징을 물려받는다.
- **에이전트는 아이디어를 생성하지 않는다.** LLM 생성 아이디어를 제공받은 조건은 개별 품질이 상승하나 결과물 간 유사도가 증가한다. 에이전트의 출력은 **분류·지표·질문**으로 한정한다.
- **배치 행위는 사용자에게 남긴다.** 사용자의 드래그 좌표는 의미 거리 보정의 학습 신호이자 개입 효과 검증의 원자료다.
- **세션은 짧은 라운드로 분할한다.** 무제한 세션은 전사 품질과 원자화 정확도를 동시에 저하시킨다.
- **재발산은 명목 그룹 형태로 수행한다.** 구체적 지시와 목표 제시가 상호작용 집단과 명목 집단 간 성과 격차를 축소한다.

## 2. 세션 상태 머신

```
LOBBY → SETUP → ROUND_ACTIVE → ROUND_REVIEW
                     ↑                ↓
                     └─ TARGETED_ROUND ┘
                                      ↓
                             SYNTHESIS → POST_PROCESSING → CLOSED
```

- 상태 전이 권한은 **전적으로 서버가 보유한다.** 클라이언트는 전이 요청만 전송하며, 허용 여부는 서버의 전이 표에서 판정한다.
- 라운드 타이머의 기준 시각은 서버 시각이다. 클라이언트는 잔여 시간을 표시만 한다.

## 3. 화면 노출 규칙

단계별로 무엇을 노출하고 무엇을 차단하는지가 본 설계의 핵심이다. 차단 항목은 구현 편의를 이유로 유입되기 쉬우므로 **린트 규칙으로 강제한다**(6.3 참조).

| 단계 | 마이크 | 노출 | 차단 |
|---|---|---|---|
| P0 룸 진입 | 꺼짐 | 방 목록, 입장 폼 | — |
| P1 대기실 | 꺼짐 | 참가자 목록, 접속 인원 | — |
| P2 세션 설정 | 꺼짐 | 문제 진술, 패싯 축, 라운드 설정 | — |
| P3 발산 라운드 | 모드에 따름 | 텍스트 카드 목록, 잔여 시간, 본인 카드 수 | **2D 캔버스, 클러스터, 색상 코딩, 에이전트 제안, 타인별 카드 수** |
| P4 에이전트 리뷰 | 꺼짐 | 전체 카드 수, 중복 후보 회색 처리 | 지표 수치, 시각화 |
| P5 타겟 라운드 | 꺼짐 | 지목된 빈 셀, 개인 입력창, 개수 목표 | **타인 입력 실시간 표시, 예시 아이디어** |
| P6 결과 구조화 | 꺼짐 | 2D 캔버스, 클러스터 라벨 | — |
| P7 포스트 프로세싱 | 꺼짐 | 전체 | — |

## 4. 단계별 명세

### P0. 룸 진입 (Room Access)

**분기** — 방 생성(Host) / 방 참여(Guest)

**인증 방침** — 로그인 사용자와 비로그인 사용자 모두 **JWT를 발급받아 단일 인증 경로를 사용한다.** 두 경로를 분리하면 WebSocket 핸드셰이크가 이원화되어 연결 레지스트리와 권한 판정이 중복된다. 게스트 토큰에는 `is_guest: true`와 서버가 생성한 닉네임을 포함한다.

**방 만들기 — Client → Server**

- `jwt_token` — 로그인 상태면 전송한다. 포함된 user id로 nickname을 DB에서 조회한다. 없으면 서버가 `guest_453434` 형식의 닉네임을 생성하고 **게스트 JWT를 발급해 응답에 포함한다.**
- `room_name` — 방 이름
- `is_private` — 비밀번호 설정 여부
- `password` — `is_private`가 true인 경우에만 유효하다

**방 참여하기 — Client → Server**

- `jwt_token` — 로그인 상태면 전송한다. 없으면 서버가 게스트 닉네임을 생성하고 게스트 JWT를 발급한다.
- `room_id` — 참여 대상 방 ID
- `password` — 비밀번호가 설정되지 않은 방에 전송된 경우 에러를 반환한다

**보안 요구사항**

- 방 비밀번호는 **bcrypt 해시로 저장한다.** 평문 저장 및 평문 비교를 금지한다.
- 비밀번호 검증 실패는 방 존재 여부와 구분되지 않는 동일 에러로 응답해 방 ID 열거를 차단한다.

### P1. 대기실 (Lobby)

**정보 표시** — 현재 참가자 목록, 실시간 접속 인원 수

**호스트 권한** — 대기열 관리 및 참가자 강제 퇴장(Kick). 호스트 권한은 독립 단계가 아니라 본 단계에서 행사되는 권한으로 정의한다.

**Kick 처리 요구사항** — DB 플래그 갱신만으로는 불충분하다. 다음 세 가지가 함께 수행되어야 한다.

- 해당 참가자의 WebSocket 연결 강제 종료
- `room_bans` 테이블 등록을 통한 재입장 차단
- 해당 참가자가 이미 생성한 카드의 처리 방침 결정(기본값: 카드는 유지하고 작성자를 익명 처리한다)

**전환** — 호스트가 P2로 전환한다.

### P2. 세션 설정 (Pre-Session Setting)

**입력 모드**

- 텍스트 전용(채팅)
- 음성 전용 — 개인 마이크 / 원 마이크 다중 화자 분리
- 혼용 모드

원 마이크 다중 화자 분리는 겹친 발화 환경에서 구현 비용이 가장 높다. **개인 마이크 모드를 기본값으로 두고**, 원 마이크 모드에는 화자 분리 실패 시 전체를 단일 화자로 처리하는 폴백을 둔다. 화자 분리가 실패하면 편중 트리거만 비활성화되고 나머지 기능은 정상 동작하도록 의존성을 분리한다.

**문제 진술 및 패싯 축 확정 — 신규 추가**

갭 지적은 세션 시작 전 확정된 축을 전제로 성립하므로, 본 항목이 누락되면 P4의 개입 근거가 개수 하나로 축소된다.

- 호스트가 **문제 진술**을 입력한다
- **패싯 축을 3~5개 확정한다.** 호스트가 직접 입력하거나, 문제 진술을 LLM에 입력해 축 후보를 제안받고 호스트가 승인·수정하는 방식을 사용한다
- 축은 세션 중 변경할 수 없다. 변경 시 기존 카드의 태그가 전부 무효화되기 때문이다

**라운드 목표치 설정**

- 1인당 최소 아이디어 발산 개수
- 라운드 제한(횟수 및 라운드당 시간)
- 아이디어 발산 단계 설정 — 프롬프팅 또는 레벨 지정

### P3. 아이디어 발산 라운드 (Ideation Round)

타이머 동작 중 자유로운 토의 및 실시간 아이디어 입력을 진행한다.

**화면 규칙** — 본 단계에서 2D 캔버스, 클러스터, 색상 코딩, 에이전트 제안을 전부 차단한다. 텍스트 카드 목록과 잔여 시간만 표시한다. 카드 목록 자체는 차단 대상이 아니다. 이전 아이디어에 대한 접근성은 조합을 발생시키는 기능으로 확인되었으므로 외부 기억은 유지해야 하며, 차단 대상은 고착을 유발하는 완성도 높은 시각 표현에 한정된다.

**타인 카드 수 비노출** — 본인 카드 수만 표시한다. 타인의 진척도를 실시간 노출하면 개수 경쟁이 발생해 카드 품질이 저하된다.

**카드 생성 요구사항**

- 음성 입력은 전사 후 아이디어 단위로 원자화한다
- **원문 스니펫과 타임스탬프를 반드시 보존한다.** 카드에서 원본 음성 구간으로 역참조가 불가능하면 신뢰가 붕괴한다
- 의역·요약을 금지한다. 원자화 과정의 의역은 이후 클러스터 전체를 무효화한다

### P4. 에이전트 리뷰 (Agent Review)

**판정 트리거 — 3종으로 확장**

초안은 개수 미달만을 개입 근거로 삼았으나, 개수는 단일 지표로 취약하다. 다음 세 트리거를 병행한다.

| 트리거 | 조건 | 계산 위치 |
|---|---|---|
| 고갈 | 최근 90초 신규 카드 수가 첫 90초의 40% 이하 | 백엔드 |
| 수렴 | 최근 카드 5장의 평균 최근접 이웃 거리가 세션 중위값 이하 | AI 서비스 |
| 편중 | 단일 화자 발언 점유율 50% 초과 | 백엔드 |

개인별 발산 목표 개수 충족 여부도 함께 확인한다.

**알림 방식** — 기준 미달 참가자에 대한 알림은 **전체 공지가 아니라 해당 참가자에게만 개별 전송한다.** 공개 호명은 품질이 낮은 카드를 채워 넣는 왜곡을 유발한다.

**지표 비노출** — 다양성 지표 수치는 내부 판정용이며 참가자에게 점수로 노출하지 않는다. 노출 시 점수 상승을 위한 무의미한 입력이 발생한다. 참가자에게 노출하는 수치는 **개수 하나로 한정한다.**

**갭 산출 — 패싯 크로스탭**

임베딩 공백은 미탐색 영역과 성립 불가능 영역이 구분되지 않으므로 채택하지 않는다. P2에서 확정한 축으로 카드를 태깅해 빈 셀을 탐색한다. LLM은 분류만 수행하므로 아이디어 동질화 위험이 없다.

예시:

| | 예방 | 발생 시점 | 사후 |
|---|---|---|---|
| 당사자 직접 | 4 | 2 | **0** |
| 주변인 대행 | 1 | 6 | **0** |
| 기관·자동화 | **0** | 3 | 1 |

**출력 형식** — 예시를 제시하면 그 특징이 후속 아이디어로 전이되므로, 출력은 질문 또는 제약 형태로 한정한다.

- 금지 — "사후 단계에 자동 알림 기능은 어떤가"
- 허용 — "사후 × 당사자 직접 칸이 0장이다. 3분간 이 칸만 채운다"
- 허용 — "기존 카드의 주체를 반대로 뒤집으면 무엇이 되는가"

### P5. 라운드 분기 및 타겟 라운드 (Iteration Check)

**분기** — "추가 발산 라운드를 진행하시겠습니까?"

- 진행 → P5 타겟 라운드를 거쳐 P3 재진입
- 종료 → P6으로 이동

**타겟 라운드 — 신규 추가**

초안은 재진입 라운드가 일반 라운드와 동일한 조건이었다. 이 경우 직전 라운드의 고갈 상태가 그대로 이어진다. 재진입 전 90초간 다음 조건으로 전환한다.

- 마이크를 끄고 **개별 입력으로 전환한다**(명목 그룹 형태)
- P4에서 산출한 **빈 패싯 셀을 지목한다**
- 타인의 입력을 실시간 노출하지 않는다
- 개수 목표만 제시한다(예: 3장)

**개입 강도** — 트리거 심각도에 따라 단계적으로 상승시킨다.

1. 약 — 개수 목표만 제시한다
2. 중 — 빈 패싯 셀을 지목하고 개별 침묵 라운드로 전환한다
3. 강 — 휴리스틱 카드를 배포한다(주체 뒤집기, 시점 이동, 제약 추가)

**개입 횟수 제한** — 세션당 2~3회로 제한한다. 도구가 주의를 점유하는 비용은 실측된 바 있으며, 개입 빈도가 과도하면 협업 흐름 손실이 개입 이득을 상쇄한다.

### P6. AI 결과 구조화 (Agent Synthesis)

**2D 캔버스 자동 시각화** — 드래그 가능한 노드 형태로 아이디어를 자동 배치한다. 카드 수가 많은 환경에서 전량 수동 배치는 비현실적이므로 자동 배치 자체는 유지한다.

**배치 확신도 시각화 — 신규 추가**

자동 배치가 완결된 상태로 제시되면 사용자는 이를 기준선으로 받아들이고 국소 수정만 수행한다. 이 경우 드래그 좌표가 학습 신호로서의 가치를 잃는다.

- 클러스터 **소속 확률이 낮은 노드는 흐리게 렌더링하고 클러스터 경계 밖에 배치한다**
- 사용자가 확신도 낮은 노드부터 조작하게 되며, 해당 드래그가 거리 보정 신호로 회수된다

**클러스터링** — 유사 아이디어를 그룹화하고 라벨을 자동 생성한다. 라벨은 제안이며 사용자 승인·수정을 거친다.

**결정론 요구사항** — 동일 입력에 동일 맵이 출력되어야 한다. 매번 배치가 달라지면 사용자 신뢰가 성립하지 않는다.

**커버리지 계산 기준** — 커버리지는 2D 투영 결과가 아니라 **원본 임베딩 차원에서 계산한다.** UMAP·t-SNE 투영 화면의 여백은 투영 아티팩트이므로 의미 공백의 근거가 되지 않는다.

### P7. 포스트 프로세싱 (Post-Ideation Tools)

- **재발산 트리거** — 특정 핵심 아이디어를 기반으로 추가 라운드를 시작한다. 초안의 "신규 세션 즉시 시작"은 채택하지 않는다. 세션을 분리하면 부모 세션의 카드·임베딩·패싯 태그가 단절되므로, **동일 세션 내 라운드로 처리하고 `parent_idea_id`만 기록한다.**
- **집중 시각화(Focus View)** — 특정 노드 중심의 서브그래프로 재구성한다.
- **초안 문서화** — 아이디어 우선순위와 회의 요약이 반영된 기획서 초안을 생성한다.
- **수동 편집** — 드래그 앤 드롭으로 그룹 생성·해제 및 재정렬을 수행한다. **모든 드래그 좌표는 덮어쓰기가 아니라 이력으로 적재한다**(5장 참조).

### P8. 세션 종료 (Session End)

최종 결과를 저장하고 워크스페이스를 내보낸 후 세션을 마감한다.

---

## 5. 데이터 적재 요구사항

- **드래그 좌표는 이력으로 적재한다.** 최종 좌표만 남기면 거리 보정의 학습 신호와 개입 효과 검증의 원자료가 동시에 소실된다.
- **개입 발생 시점과 트리거 종류를 기록한다.** 개입 전후 15분 구간의 커버리지 증가분과 신규 카드의 최근접 이웃 거리 변화가 효과 검증 지표이며, 이를 산출하려면 개입 시각이 남아 있어야 한다.
- **카드는 원문·타임스탬프·화자·`parent_idea_id`를 함께 보관한다.**

---

## 6. 구현 제약

### 6.1 지표 계산 위치

- 벡터가 불필요한 지표(개수, 화자 점유율) — 백엔드에서 계산한다
- 벡터가 필요한 지표(중복도, 커버리지, 신규성) — AI 서비스에서 계산한다
- **최종 개입 판정 주체는 백엔드 단일 모듈로 고정한다.** 판정 로직이 양쪽에 분산되면 트리거 재현이 불가능해진다

### 6.2 화자 분리 의존성 격리

화자 분리 실패 시 편중 트리거만 비활성화되고 전사·원자화·클러스터링은 정상 동작해야 한다.

### 6.3 시각화 잠금 강제

P3·P5 화면에서 캔버스 컴포넌트 import를 **린트 규칙으로 금지한다.** 규칙으로 고정하지 않으면 개발 편의를 이유로 캔버스가 발산 화면에 유입되고, 설계의 핵심 근거가 무효화된다. 규칙 파일에 금지 사유를 주석으로 명시한다.

---

## 7. 미결 사항

- 타겟 라운드의 빈 셀 지목 시, 셀을 전원에게 동일하게 제시할지 참가자별로 분배할지 결정한다
- 카드 원자화 단위의 기준(발화 1건 = 카드 1장인지, 1발화 내 복수 아이디어를 분할할지)을 확정한다
- 텍스트 전용 모드에서 화자 분리가 불필요하므로 편중 트리거를 카드 수 기준으로 대체할지 결정한다
- Kick된 참가자의 기존 카드 처리 방침을 최종 확정한다
